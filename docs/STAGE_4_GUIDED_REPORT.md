# Этап 4A — минималистичный пошаговый подбор

Новый запрос пользователя 25.10.2026. Ветка stage/4-guided-admission-flow,

## Путь пользователя

Главное меню: четыре действия. Подобрать программы → предметы (по умолчанию
русский/математика/информатика) → по одному баллу 0–100 → диплом перечневой олимпиады
(нет/победитель/призёр, необязательные уровень/предмет) → вуз или все десять → программы.
Можно пропустить пока неизвестные баллы, изменить один результат, вуз, финансирование,
искать программу по названию/коду и открыть источник. ИИ/AI/ML распознаются в поиске.

Списки листаются кнопками; возврат из карточки сохраняет страницу и поисковый запрос.
Разные коды и basic_higher отличаются в названиях кнопок. Источники вынесены в ссылки-
кнопки; в пользовательском пути не нужно вводить команды, ID карточек или формулы.
Старые команды сохранены в /help. Сценарий прогресса ЕГЭ — отдельная существующая функция;
его дальнейшее упрощение и углублённый подбор входят в следующие продуктовые части.

## Данные и честность вывода

Выбранная кампания по умолчанию 2027. Справку по минимумам 2026 нужно запросить
явно; её просмотр не переписывает цель 2027. Фильтр школьных минимумов пока
документирован только для МИФИ Москва 2026. Показывается сумма ЕГЭ без автоматического
назначения баллов за диплом; условия профиля/кампуса и категорию нужно сверить.

Заявление о дипломе сохраняется между шагами как самодекларация. Уровня/предмета
недостаточно для права БВИ: нужны название олимпиады, год/класс диплома, условия
конкретной годовой программы и подтверждение. БВИ/ИД автоматически не назначаются.
Текущие списки — каталог или направления с выполненными минимумами, не программы
«с высокой вероятностью». Калиброванный артефакт по-прежнему отсутствует.

523 профильные записи десяти вузов, история/правила и все прежние функции сохранены.
Новых реальных пользовательских данных, профилей, таблиц или миграций нет.
Контекст передаётся самой перепиской/кнопками Telegram; в D1/файлах/логах он не хранится.
Это не заявление о юридической пригодности Telegram для полноценного публичного сервиса.

## Протокол и проверки

src/guided.ts: компактное состояние, проверка диапазонов и согласованности, payload
до 64 ASCII-байт. Числовой reply принимается только к каноническому тексту собственного
бота. Обработка callback проверяет private chat, совпадение sender/chat и имя бота.
Неверная/старая кнопка получает ответ с восстановлением, не бесконечный retry.
Bridge подтверждает callback, редактирует окно и переживает double-click/not-modified
и истёкший ack. Никакие Bot API методы вне разрешённого списка не вызываются.

Новые тесты покрывают полный путь, неверные баллы, чужого бота/чат, payload-границы,
сохранение диплома/поиска/страницы, редактирование, разделение 2026/2027 и отсутствие D1.
Полный check: 64 Node + 101 Python = 165 тестов. Обновлённый реальный workerd smoke
проходит тот же путь с синтетическими сообщениями и callback; внешний Telegram API
не участвует в тестах. Build/migrations, старый D1 smoke, artifact replay, EGE grid
и fault/load probe сохраняются в полном quality. Новые персональные источники не собирались.

Незавершённое: полные годовые олимпиады/льготы всех вузов, сопоставимая история,
реальная калибровка, сохранённые профили и публичный пилот. Следующие этапы продолжают
эту реализацию, не объявляя неизвестные высокие вероятности известными.
