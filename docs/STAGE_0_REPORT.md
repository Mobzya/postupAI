# Этап 0 — результат

Дата: 23 октября 2026 года. Проект: Ballnik / Admission Forecast 0.1.0.
В рабочей папке не было исходного репозитория; создан новый проект без внешнего remote.
Выполнен этап 0 и подготовлена основа этапа 1. Система ещё не прогнозирует поступление.

## 1. Архитектура

Telegram → TypeScript Worker → D1. Python вне webhook валидирует данные и формирует аудит.
Позднее Python соберёт снимки, извлечёт агрегаты и построит компактные модельные артефакты;
Worker будет применять проверенные правила и лёгкий расчёт по этим артефактам.
Веб-сервера/VPS, обязательных платных API, LLM и купленного домена в архитектуре нет.

Сейчас есть защищённый webhook, минимальный профиль и удаление, начальные URL,
контракт расчёта конкурсного балла и проверки распределений. Нет загрузки результатов,
автоучёта олимпиад, реального каталога и вероятностей. Правила вузов не зашиты в код.
Подробности: [ARCHITECTURE.md](ARCHITECTURE.md).

## 4. Схема базы

Все 15 запрошенных сущностей представлены. Дополнительно: `import_batches`,
`source_snapshots`, `admission_curves`, `telegram_updates`. Всего 19 таблиц.
SQL: `migrations/0001_foundation.sql`, `0002_source_entrypoints.sql`,
`0003_revision_integrity.sql`. Связи и семантика: [DATABASE.md](DATABASE.md).

Отдельные категории бюджета, двух видов квот, целевого, БВИ, платного,
грантов и специальных отборов. Название, код, кампус и правила версионируются.
Исторические метрики хранят единицы, методику и снимок источника, а год связан
через версию программы. Исправления добавляют ревизии, UPDATE/DELETE истории запрещены.
`NULL` требует причину отсутствия; ноль сохраняет свой буквальный смысл.

Пользователь определяется HMAC-псевдонимом. `/delete_data` каскадно удаляет профиль,
историю баллов, достижения, избранное и результаты прогнозов. Реальные баллы и
достижения пользователей в этом этапе не вводились и не сохранялись.

| Проверка | Результат |
| --- | --- |

| `npm test` | 18 из 18 |

| `npm run validate:data` | Реестр и пустой каталог валидны; модель отключена |
| `npm run deploy:dry` | Worker собран без публикации: 21.59 KiB, gzip 4.71 KiB |
| `npm run db:local` | Все 3 миграции применены в локальной D1 Wrangler |
| `npm run test:smoke` | Настоящие HTTP → workerd → D1: health, start, profile, отказ прогноза, delete |
| Повтор генерации DATA_AUDIT | Текст и SHA-256 идентичны при тех же входах |

32 автоматических теста покрывают диапазоны/нормировку, отсутствие вероятностей
при нехватке данных, подсчёт по synthetic-правилам, альтернативные экзамены и ДВИ,
раздельные категории, валидацию provenance, missing/conflict, миграции, цепочки
ревизий, атомарность receipt и изменения профиля, отсутствие SQL-утечек в ответах,
проверку секрета, неподдерживаемые/крупные запросы и удаление зависимых данных.

Тесты распределений проверяют контракт будущей модели, а не качество прогноза ЕГЭ.
Эмпирическая калибровка, полная обработка прав олимпиад и модельные тесты пока невозможны:
их реализация отложена до аудита. Живой Telegram и реальный аккаунт Cloudflare не тестировались.
CPU в реальном бесплатном Worker не измерялся.

Начальный запуск dev столкнулся с ограничением чтения сетевых интерфейсов среды.
Явная привязка к 127.0.0.1 и inspector-port=0 устранила ошибку; это внесено в npm run dev.

## 7. Риски и нерешённые проблемы

| Риск | Что предусмотрено / что остаётся |
| --- | --- |
| Неполные/закрытые/динамические источники | Раздельные статусы разведки и извлечения; ручная проверка, без обхода ограничений |
| Различия кампусов, программ и общих конкурсных групп | Стабильный ID, версии и competition_group_key; нужен ручной каталог |
| ДВИ и разные шкалы конкурсного балла | Отдельные экзаменационные компоненты; реальные правила ещё предстоит описать |
| Изменение правил 2027 и структуры образования | Годовые версии, поддержка basic_higher; не переносить автоматически правила 2026 |
| Прогресс по пробникам без индивидуальной истории | Конфиг явно вымышленный и отключён; нужна валидация или сбор добровольных траекторий |
| Малая история, сдвиг конкуренции и корреляция предметов | Позднее сценарии и совместное распределение; сейчас никаких процентов |
| Несколько конфликтующих источников одного числа | Статус conflict есть; множественные связи provenance расширить на этапе 1 |
| CPU и квоты бесплатной платформы | Лёгкий Worker, индексы, офлайн-вычисления; production profiling ещё нужен |
| Telegram-повторы и задержки | Атомарные receipt на 7 дней; возможны повторы ответа, очистка ограничена 1000/сутки |
| Ротация HMAC-ключа и старые бэкапы | Ключ не терять; перед ротацией/восстановлением нужна процедура доступа и удаления |

Сложные парсеры, импорт программ, публикация моделей, диалоги полного профиля,
достижения, сравнения и уведомления остаются будущими задачами.

## 8. Следующий конкретный шаг

Начать этап 1 с доступного раздела МИФИ: перечислить все релевантные программы и кампусы,
зафиксировать критерии включения, сохранить официальные документы и разработать адаптер
по снимкам. Для первой конкурсной группы вручную сверить год, правила, экзамены,
категорию, шкалу, места и проходной; проверить доступность 2023–2026.
После пилотной проверки расширять сбор на остальные источники и перегенерировать аудит.
К ML не переходить до понимания полноты и сопоставимости данных.

Публичный деплой, вход в аккаунты, регистрация webhook и отправка сообщений
реальным пользователям в рамках этого этапа не выполнялись.
