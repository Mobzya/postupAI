# Локальные операции и CI

## Обычный цикл

1. Прочитать AGENTS.md/PROJECT_STATE.md, проверить git status и текущую ветку.
2. Запустить npm run bot:check и bot:local с секретами в игнорируемом .dev.vars.
3. Перед Wrangler-проверками остановить runner. Выполнить npm run quality.
4. При изменении данных: verify_rules_import.py (цепочка всех этапов), public_backup.
5. Обновить release/state/report, проверить секреты, коммит и PR, снова запустить runner.

Не запускайте два poller одного бота. Webhook runner сам не удаляет.
Логи не содержат токена, chat/user ID, payload или результатов пользователя.
/health — обезличенная проверка версии/режима; отсутствие профилей и прогнозов явно показано.

## Офлайн-воспроизводимость

python3 -m pipeline.verify_artifacts сверяет канонические данные и отдельные
публичные индексы Worker с повторным извлечением из компактных представлений.
В частности, ручная правка минимума в public_rules.json не проходит CI, даже если
основной dataset.json остался прежним. Проверяются гипотезы и блокировка вероятностей.
Данные не перезаписываются этой проверкой. Полные новые raw-документы хранятся
отдельно от Git, их SHA сохранены; CI проверяет извлечённые представления, не
скачивает заново и не доказывает доступность оригиналов на текущую дату.

## Бэкап публичного слоя

pipeline.public_backup create --directory НОВАЯ_ПАПКА создаёт SQLite заново из
миграций и полной проверенной цепочки импортов. Все пользовательские таблицы пусты.
manifest.json содержит SHA файла, миграций, датасетов, версию кода и counts.
Существующая папка не перезаписывается. restore требует новый destination,
проверяет SHA до открытия, integrity/FK/counts и отсутствие пользовательских данных,
затем выполняет фактическое SQLite backup/restore и повторную проверку.

Это резервирование публичного датасета и проверка схемы, не резервирование
production D1/профилей и не архив самих raw-источников. Путь к raw в базе не является
копией документа. Для постоянного размещения нужно отдельное хранилище снимков,
ретенция и проверка восстановления настоящей D1 после согласования инфраструктуры.

## GitHub Actions

.github/workflows/quality.yml: push/PR/manual, Ubuntu 24.04 standard runner, Node24,
Python3.12, npm ci, pinned Python-зависимости, тесты, artifact replay, D1 import,
два workerd smoke и реальное восстановление публичного бэкапа. Poppler устанавливается
явно: проверка PDF исходного слоя 1A вызывает pdftotext и при офлайн replay.
Actions закреплены SHA официальных релизов, проверенных через GitHub API 25.10.2026:
checkout v7.0.1, setup-node v7.1.0, setup-python v7.1.0.
Права contents:read, credentials не сохраняются checkout, секреты не требуются,
запуски одной ветки отменяют предыдущие, timeout 15 минут. Автодеплоя нет.

Внешний бот не участвует в CI и входящие Telegram updates CI не читает.
Бесплатные лимиты/бюджет облака должны быть проверены перед постоянным хостингом;
текущая локальная работа не требует покупки сервисов или Cloudflare credentials.
