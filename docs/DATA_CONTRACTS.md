# Контракты этапа 0

Реестр `data/source_registry.json`: `schema_version: 1`, массив `sources`.
Поля и допустимые статусы проверяет `pipeline.validate.validate_registry`.
`last_checked_at` относится к проверке входной страницы; это не дата проверки
правил или извлечённых чисел. `years: []` означает, что годы документа не изучены.
`completeness: null` означает отсутствие оценки. `parsing_status: not_started`
относится к извлечению; `discovery_status` отдельно описывает 403, JS и техработы.

Каталог `data/normalized/catalog.json`: версия схемы, флаги `catalog_complete`,
`is_synthetic`, массив `records`. Пока массив пуст; полным каталог не объявляется.
Будущая строка соответствует program/year/track/revision и содержит `campus`,
`degree`, `source_id`, `verification_status` и все поля аудита из `catalog_scope.json`.
Отсутствующее поле должно быть представлено `null`, а не удалено и не равно 0.

Числовое поле имеет объект `value`, `status`, `unit`, `source_id`, `year`,
`methodology`. При `value: null` обязательны `status: missing` и `missing_reason`.
Сейчас проверяются базовые формы и происхождение; схемы содержимого правил,
перечня экзаменов, БВИ и распределений должны расширяться вместе с адаптерами этапа 1.
Эта заготовка не является валидатором всех будущих данных приёма.

Распределение: список `{score, probability}` без повторов score, с конечными
неотрицательными вероятностями и суммой 1 ± 1e-9. ЕГЭ: score в 0–100.
Общий конкурсный балл имеет отдельный верхний предел по правилам, включая ДВИ и ИД.
Невалидный объект не нормируется молча.

`ScoreRules` в TypeScript — каркас для уже проверенных простых правил.
`slots` — обязательные экзаменационные позиции; внутри позиции альтернативы.
`key` может иметь вид `dvi:math`, `maximum` задаёт шкалу, `minimum` — допуск.
Выбирается лучший из допустимых представленных альтернативных результатов.
Отсутствующий обязательный экзамен и неподтверждённые правила не дают числового итога.
БВИ/квоты/гранты возвращают `unsupported_track`: отдельные правила ещё не созданы.
Баллы достижений принимает только вызывающий доверенный модуль после проверки.

Для публикации вероятности будущий артефакт должен содержать год, категорию,
ID правил, хеши модели/данных/конфига, сценарий, подтверждённую область применимости
и отчёт проверки. Сейчас таких артефактов нет, поэтому API прогнозов закрыт.

Сетевые адаптеры будут читать сохранённые снимки через `Adapter.extract`.
Автосбор обязан ограничивать частоту, сохранять ошибки и не обходить ограничения.
На этапе 0 запросы выполнялись только для разведки входных официальных страниц.
