# Этап 6 — техническая репетиция и протокол реального пилота

25.10.2026. Ветка stage/6-technical-pilot, база этапа 5 e690ca5.
Человеческий пилот, реальная калибровка и готовность кампании 2027 **не выполнены**.
Созданы и проведены технические проверки с синтетическими сообщениями/баллами.

## Проверки

scripts/ege_grid.mjs: 297 комбинаций стартовых баллов 0–100, часов 0/6/40,
регулярности 0/0.5/1, горизонта 0/180/730 дней, три сценария и три предмета.
3564 распределения проверены на нормировку, границы, сценарные массы, монотонность
центров, нулевой рост при нулевой подготовке или отсутствии времени. Это не проверка
по результатам учеников; эмпирическая точность не заявляется.
Локальная Node CPU/wall метрика записана для воспроизведения окружения и не заменяет
профилирование Cloudflare isolate CPU.

scripts/pilot_probe.py: настоящий локальный workerd без D1/профилей. Неверный
секрет 401, JSON 400, слишком большой body 413, MIME 415, длинное сообщение 400;
группы игнорируются, неверный ЕГЭ отклоняется. Затем 100 последовательных запросов
после прогрева: median 8.1 мс, p95 24.6 мс.
40 запросов четырьмя клиентами: median 15.3 мс, p95 25.1 мс.
Это latency loopback в текущей среде, не Telegram SLA, не real-user load и не CPU Free.
Реальный Telegram Bot API эти проверки не вызывают; poller предварительно остановлен.

Полный npm run quality: 49 Node + 92 Python = 141 тест, TypeScript, canonical/public
replay, Worker dry build, миграции, D1 smoke, stateless flow, grid и probe.
Оба новых инструмента включены в CI. Предыдущий remote CI этапа 5 успешно прошёл:
https://github.com/Mobzya/postupAI/actions/runs/40146204569.
Машинный результат: docs/stage_6_verification.json. Локальный бот перезапускается после проверок.

## Дальнейшая приёмка

PILOT_PROTOCOL.md описывает будущие задачи пользователей, добровольные данные,
агрегированные UX-метрики и отдельную научную проверку. Набор участников, рассылки,
интервью и сбор пробников не проводились. Законная схема хранения должна быть
проверена до сохранения реальных исследовательских данных.

STAGE_STATUS.md сопоставляет каждый этап с выполненной частью и открытыми
критериями. Нет подтверждённых конкурсных совокупностей, калиброванного артефакта,
полных каталогов/правил, профилей и Cloudflare deployment. Поэтому продукт остаётся
локальным preview, а не принятым финальным MVP. Следующая полезная работа — закрывать
документированные пробелы данных и правил, сохраняя те же запреты на выдуманные факты.
