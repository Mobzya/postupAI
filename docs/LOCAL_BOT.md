# Локальный Telegram-бот

Задание пользователя от 24.10.2026: подключать текущий результат этапов к
[@postupAI5_bot](https://t.me/postupAI5_bot), пока работать локально без Cloudflare.
Режим: Telegram getUpdates → Python bridge → workerd на loopback → Telegram sendMessage.
Прямых сообщений без входящего обновления runner не отправляет.

## Запуск

Установить Node 24+, Python 3.12+, выполнить `npm ci` и установить requirements-data.txt.
В `.dev.vars` поместить `TELEGRAM_BOT_TOKEN` и независимый `TELEGRAM_WEBHOOK_SECRET`
(32–256 символов A–Z/a–z/0–9/_/-). Файл исключён из Git; установить права 0600.
Не передавать реальные секреты в командной строке или публичных issue/PR.

```bash
npm run bot:check
npm run bot:local
```

Проверка не читает обновления: вызывает только getMe и getWebhookInfo. Имя бота
должно совпадать с `config/bot.release.json`. При существующем webhook runner
останавливается; конфигурация Telegram автоматически не меняется.

Запуск выбирает свободный loopback-порт, поднимает Worker без D1, проверяет
версию, запрет профилей и авторизацию локального endpoint, затем включает long polling.
Можно открыть бот в Telegram и отправить `/start`, затем `/status` или `/sources`.
Меню команд устанавливается при старте runner. Прогноз честно сообщает о недоступности.

## Хранение и ограничения

Полные обновления, тексты сообщений, offset и chat/user ID существуют только в памяти.
Логи содержат статус запуска и обезличенные ошибки соединения. Токен не попадает
в argv, исходники и логи; вывод дочернего Wrangler подавлен.
Параметры синтетических тестов не являются реальными пользовательскими данными.

Профили по умолчанию отключены. `wrangler.bot.toml` не содержит D1 binding, cron
или других хранилищ. Старые profile-функции сохранены под явным opt-in только
для локальных синтетических тестов; это не разрешение хранить реальные профили.

Одновременно запускать один poller. Локальный flock предотвращает дубликат в той
же рабочей папке, Telegram 409 останавливает конфликтующий runner из другой среды.
Webhook не удаляется, накопленные updates не сбрасываются.

После успешного ответа offset продвигается в памяти. Сетевой сбой после доставки
сообщения или перезапуск может привести к повторному ответу: exactly-once не обещается.
Если пользователь заблокировал бота перед ответом, недоставляемое обновление пропускается.

Рабочая среда временная: после её остановки/приостановки бот не отвечает. Это локальная
разработка, не круглосуточный хостинг. При возобновлении работы runner запускается снова.

## После этапа

Обновить `config/bot.release.json` и ссылку на ревью. `/status` читает сводку данных
из нормализованных metrics; отсутствие проверенной модели не заменяется процентами.
Перед другими Wrangler-проверками остановить runner (Ctrl+C), выполнить проверки
последовательно и затем снова запустить `npm run bot:local`.
Проверки: `npm run check`, `npm run deploy:dry`, `npm run db:local`,
`npm run test:smoke`. Последние два относятся к сохранённому D1-прототипу с синтетикой;
локальному stateless-боту D1 не нужна.

Официальные API: [Telegram getUpdates](https://core.telegram.org/bots/api#getupdates),
[ответ через webhook](https://core.telegram.org/bots/faq#how-can-i-make-requests-in-response-to-updates).

## Кнопки и текущие функции

/start показывает клавиатуру. Выберите поиск, ЕГЭ, конкурсный балл, правила,
историю или сравнение. На подсказку можно ответить обычным Telegram reply:
контекст передаётся самим Telegram, сервер не хранит сессию. Ответы на чужие
сообщения/другого бота не считаются вводом в сценарий.

/search ВШЭ математика страница=2 показывает следующую часть каталога. /program
открывает карточку по коду из результата, /compare сравнивает 2–3 таких кода.
Коды — публичные идентификаторы записей текущего каталога, не конкурсов.
/save и /favorites отключены, сохранения прогнозов/персональных данных нет.
Полноценный product flow со сброшенными ограничениями не объявляется готовым.
Дополнительная проверка: python3 scripts/smoke_bot.py (только синтетика).

## Новый путь /pick

Главное меню: Подобрать программы / Каталог / Прогресс ЕГЭ / Возможности.
/pick открывает выбор предметов. Баллы вводятся по одному ответом на подсказку,
диплом/уровень/предмет и вуз выбираются inline-кнопками. Программы можно искать
внутри вуза или по всем десяти, листать, открывать и возвращаться на ту же страницу.

Bridge получает message и callback_query, подтверждает callback и редактирует
сообщение для навигации. При числовом вводе отправляет ForceReply. Повторное нажатие
и просроченное подтверждение не останавливают poller. Старые команды работают.
Состояние передаётся в сообщениях/кнопках Telegram и проверяется при каждом ответе;
сохранённого профиля/D1/логов с данными нет. Историей переписки управляет Telegram.
Это технический локальный preview, не подтверждённая правовая схема публичного сервиса.
