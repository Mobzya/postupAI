# Словарь данных этапа 1A

## Сущности и идентичность

| Сущность | Значение | Реализация |
| --- | --- | --- |
| Университет | Юридическая/организационная принадлежность | institutions, существующая таблица |
| Кампус | Москва отдельно от филиалов | campuses, FK на вуз |
| Направление/специальность | Национальный код и уровень образования | study_fields; название фиксируется в годовом источнике |
| Образовательная программа | Конкретный профиль и подразделение; один код имеет много программ | programs + program_versions |
| Приёмная кампания | Вуз + кампус + год | admission_campaigns |
| Направление кампании | Официальный перечень направлений московского приёма 2026 | campaign_field_offerings, с PDF provenance |
| Конкурсная группа | Одна установленная совокупность условий конкурса | competition_groups; candidate или confirmed |
| Участник группы | Направление и, если известно, конкретная версия программы | competition_group_members, связь многие ко многим |
| Условия конкурса | Финансирование/квота, форма, основание поступления | competition_conditions |
| Распределение мест | Одно опубликованное число для объявленной области | seat_allocations + seat_allocation_members |
| Историческое наблюдение | Одна строка опубликованной статистики, даже если группа неизвестна | admission_observations |

Миграция 0004 добавляет 10 таблиц к 19 таблицам этапа 0. Старые таблицы не удалены.
В program_versions добавлены nullable FK `campus_id`, `field_id` и `catalog_metadata_json`.
`admission_tracks` этапа 0 оставлена совместимой, но новые общие места через неё не размножаются.
Подтверждённые группы в этом срезе отсутствуют; 39 кандидатов отражают области распределений мест.

## Исторические строки: data/normalized/mephi/history.json

| Поле | Смысл |
| --- | --- |
| id | Хеш идентичности source URL + год + физическая строка + снимок + версия адаптера |
| row_key | Стабильный адрес строки конкретного источника и года; не равен коду направления |
| year / campus_id | Год таблицы и московский кампус; не год из общего меню сайта |
| official_code | Код, буквально опубликованный в этой строке; null в таблице 2015 без кодов |
| official_name / division | Название и подразделение как в источнике; null означает, что подразделение не указано |
| competition_category | budget_unspecified: страница посвящена бюджету, но квоты и основной конкурс не разделены |
| competition_group_id | null, пока конкретная историческая группа не установлена |
| group_mapping_status | unresolved или confirmed; кандидат группы не допускается как confirmed |
| threshold_status | numeric, bvi_only, not_published, not_offered, parse_error, manual_review |
| cutoff | Проходной конкурсный балл; может быть выше 300; null для ненумерического статуса |
| cutoff_raw / threshold_type_raw | Исходные значения ячеек без подмены «Нет» числом |
| mean_ege_score | Средний балл одного ЕГЭ на шкале 0–100, только при соответствующем заголовке |
| mean_entrance_total | Средняя сумма вступительных баллов; не делится автоматически на 3 и не названа средним ЕГЭ |
| mean_*_status | published или not_published; отсутствующее поле не заменено нулём |
| provenance | URL, source ID, SHA-256, путь снимка, версия адаптера, таблица, строка, XPath, raw cells и HTML-фрагмент |
| review_status / warnings | Потребность в установлении группы и иные ограничения |

Если не удаётся распознать год/схему таблицы, сбор останавливается с parse_error,
записывает extraction_errors.json и не заменяет предыдущий успешный набор нулями.
Неизвестный текст порога получает manual_review. Отсутствие строки само по себе
не означает not_offered: такой вывод без явного источника запрещён.

## Программы и места

`catalog.json`: 82 строки профилей двух HTML-таблиц. `name` — профиль, а не название
направления; `official_code`, `field_name_raw`, `division`, URL профиля/плана сохраняются отдельно.
`tags`: Mathematics, Computer Science, Artificial Intelligence / ML, Engineering, Physics, Other.
Теги получены открытой эвристикой и имеют статус heuristic_reviewable; они не являются
ключами идентичности и не влияют на определение конкурса.

`campaign_association=current_site_navigation_not_individual_confirmation`: каталог расположен
на сайте кампании 2026, но для каждого профиля год и доступность отдельно не подтверждены.
`admission_status` различает наличие направления в официальном перечне 2026 и потребность
в проверке. Это не разрешение на автоматический прогноз.
ID программы воспроизводится по кампусу, коду, подразделению и названию. Это начальная
идентификация: переименование/объединение профиля требует явного ручного сопоставления,
а не автоматического склеивания по коду или объявления новой независимой возможности.

`seats.json`: 39 распределений. `places` хранится один раз, `codes` содержит все направления
общей ячейки. `funding=federal_budget_total` включает неразделённые бюджетные категории,
а не только основной конкурс. `funding=paid` — платный план; строка «Лечебное дело
(иностранцы)» получает applicant_basis=foreign_applicants. Суммы 1011 и 492 относятся
к опубликованным областям источника и не являются местами одного общего конкурса.

## История и повторный импорт

Снимки content-addressed, исходные bytes проверяются SHA-256. Нормализованные факты
перед импортом повторно извлекаются из этих bytes. Одинаковый import даёт 0 новых строк.
Новый снимок или новая версия адаптера создают новые наблюдения и версии программ;
старые факты защищены от UPDATE/DELETE. Строки наблюдения одного кода не схлопываются.
Версия адаптера входит в уникальность фактов и ID; версии парсеров не следует менять
без смены ADAPTER_VERSION после выпуска этого этапа.

Места находятся в отдельной таблице, поэтому JOIN с программами не разрешает суммировать
одно и то же распределение повторно. Для агрегации использовать уникальные allocation ID.
Полные HTML/PDF в D1 не сохраняются; там метаданные, нормализованные значения и небольшие
фрагменты строк. JSON-фрагменты HTML — недоверенные данные, их нельзя вставлять в UI как HTML.

`data/source_registry.yaml` — расширенный реестр, сериализованный JSON-подмножеством YAML 1.2.
`source_verified` в матрице означает успешное чтение содержательной страницы, а не проверку
всех ссылок. linked_not_read, javascript_shell_only, failed и unknown сохранены явно.
Старый source_registry.json обслуживает совместимость этапа 0; актуальные статусы — в YAML.
