# База D1

Три миграции: `0001_foundation.sql`, `0002_source_entrypoints.sql`,
`0003_revision_integrity.sql`. SQLite-совместимый SQL, JSON CHECK, FK, индексы и триггеры.
Миграция 0002 добавляет только 10 вузов и 10 входных URL, без программ и баллов.

| Сущность | Назначение и связи |
| --- | --- |
| `institutions` | Стабильный ID вуза и официальный URL |
| `programs` | Стабильный внутренний ID программы, вуз, классификация и её обоснование |
| `program_versions` | Год, ревизия, название, код, кампус, форма и уровень; ссылка на снимок |
| `admission_years` | Отдельный справочник годов кампании |
| `admission_tracks` | Категория конкурса и ключ конкурсной группы для версии программы |
| `admission_rules` | Версии правил конкретного конкурса, статус проверки, снимок |
| `historical_metrics` | Число, единица, методика, ревизия, статус, источник; год через track → version |
| `score_distributions` | Обезличенное распределение, определение популяции, шкала и методика |
| `source_records` | URL, тип документа, годы, проверка, извлечение, статус, надёжность и полнота |
| `source_snapshots` | Неизменяемые снимки с SHA-256 и временем |
| `import_batches` | Идентичность набора и версии адаптера; защита от повторного импорта |
| `model_versions` | Хеши артефакта, данных, конфигурации; версия кода и допущения |
| `admission_curves` | Кривая для конкретных track/rule/model/scenario |
| `user_profiles` | Только HMAC-псевдоним, версия согласия, настройки и дата |
| `user_score_history` | Предмет, пробник, балл, дата/тип, часы, регулярность, цель, дата экзамена |
| `user_achievements` | Структурированные достижения и статус подтверждения |
| `saved_programs` | Избранные стабильные program ID пользователя |
| `forecast_results` | Будущие результаты с входами, правилами и двумя версиями моделей |
| `telegram_updates` | Временные update ID для идемпотентности, без пользователя и текста |

Все четыре зависимые от профиля таблицы имеют `ON DELETE CASCADE`;
вместе с `user_profiles` удаляются данные в пяти таблицах.
Индексы поддерживают доступ по пользователю, вузу, программе, году и метрике.

Категории: `general_budget`, `special_quota`, `separate_quota`, `targeted`,
`bvi`, `paid`, `grant`, `special_selection`. БВИ в этой модели — отдельный механизм
приёма, не произвольное добавление 100 баллов и не самостоятельная квота мест.
`competition_group_key` связывает программы одного конкурса: их нельзя складывать
как независимые возможности или дважды учитывать одни места.

История метрик, снимков, версий программ, правил, распределений, моделей и кривых
защищена от UPDATE/DELETE. Исправление добавляет следующую ревизию со ссылкой
`supersedes_id`; триггеры проверяют принадлежность той же сущности/году/категории.
Представление `latest_historical_metrics` возвращает последнюю ревизию, включая
конфликтную или отсутствующую: запрещено молча откатываться к удобному старому числу.

`NULL` — нет значения, с причиной отсутствия. Ноль — явно опубликованный ноль.
SQL проверяет структуру JSON и базовые ограничения; нормировку распределений,
полноту provenance, согласованность источников и смысл правил проверяет Python/TS.
Полный импорт и публикация артефактов ещё не реализованы.

`score_distributions` хранит агрегаты, не фамилии или номера документов абитуриентов.
Старые snapshots сохраняются при переимпорте; hash и adapter version определяют batch.
Один снимок сейчас связан с записью метрики; несколько конфликтующих первоисточников
потребуют расширения provenance на этапе 1, без потери старых сведений.
